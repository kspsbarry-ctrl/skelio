## 測試界限

Chrome 探測被中斷，沒有完成桌面或手機操作，沒有截圖。下面說「確認」只表示程式路徑必然如此，不表示已在瀏覽器看見畫面。鏡頭有沒有真的跟著滾、標本有沒有浮起或穿出缸壁、WebGL 中斷後會不會黑屏，都還沒實測。

## P1 確認的程式缺陷

### 1. 捲動鏡頭綁錯捲動容器

`index.html` 第 39–41 行讓 `html` 與 `body` 的直向溢位都是 `hidden`，進入後只有 `body.inside` 打開 `overflow-y: auto`。第 47 行把捲動軌道加到 `560vh`。第 1537–1563 行的 Lenis 與 ScrollTrigger 捲的是視窗；Lenis 1.1.13 在 wrapper 為 window 時寫的是 `documentElement.scrollTop`。第 1780–1788 行的手機直向拖曳也讀 `window.scrollY`。

`html` 溢位關閉時，視窗不該成為捲動埠；`body` 只有 `min-height: 100%`，高度隨內容長大，自身也不會出現捲軸。滾輪、拖曳、進度條可能都停在 0。

建議：進入後讓 `html` 和 `body` 一起可捲，或把 Lenis 的 wrapper 設成實際在捲的那個元素，ScrollTrigger 用同一個 scroller。

驗收：進缸後滾一輪，`#scrollPctLabel` 從 0% 走到 100%，鏡頭繞標本一圈，RESET 回到 0%。

### 2. 縮放滾輪同時推動鏡頭路徑

第 1818–1831 行在 Alt、Ctrl 或已聚焦標本時只對畫布 `preventDefault`，沒有停止冒泡。Lenis 1.1.13 開著 `smoothWheel` 時仍會吃掉同一個滾輪並捲動，原始碼沒有先因 `defaultPrevented` 而放棄。

結果是想拉近標本時，環繞路徑也在跑。

建議：縮放時 `stopPropagation`，或 Lenis 忽略已取消的滾輪。聚焦標本時要嘛凍結路徑，要嘛把滾輪定義成只做縮放。

驗收：進缸後按住 Alt 滾輪，距離改變，進度百分比不變。點選一隻標本後再滾輪，只縮放，不換路徑位置。

### 3. 標本載入可以重複，離開後仍可能留在畫面上

`openBox`（第 1722–1732 行）看到 `insectGroups` 還是空的就再叫一次 `placeBeetles`。`placeBeetles`（第 1429–1453 行）沒有進行中的鎖，載入完成也不看目前是不是已經離開。`leaveBox`（第 1735–1744 行）只隱藏當時已經在陣列裡的物件。

快開快關，或在第一批載入完成前再打開，會產生兩組標本；晚到的模型會在封面階段仍然可見。

建議：用一個放置代號。開始放置、離開、重新進入都讓舊代號失效；完成時代號不符就不要加入場景。

驗收：載入途中連按 OPEN、BACK、OPEN。場景裡每種標本只出現一次，回到封面時標本不可見。

### 4. 載入失敗沒有重試，檔案協定警告會被蓋掉

`index.html` 第 1927–1934 行先寫「請以 Live Server 開啟」，`boot` 隨即在第 1315 行改成 `LOADING TANK`。失敗時第 1437、1461–1463 行只改狀態文字，沒有重試按鈕。`showcase.html` 第 826–832 行同樣先警告，接著 `focusIndex` 把提示改成 `LOADING`（第 631–635、664–676 行）。選同一個標本有機會再載一次，但畫面上沒有重試。

建議：失敗狀態留下按鈕，重新執行原本那一次載入。`file:` 警告要留在畫面上，不要被 LOADING 蓋掉。

驗收：斷網或 `file://` 開啟時看得到原因與重試；按重試會再請求該 glb。成功後提示才變成可操作。

### 5. 標本頁沒有縮放，手機橫向拖曳不能 360 度旋轉

`showcase.html` 第 761–766 行滾輪一律換上一隻或下一隻。第 739–745 行在手機版式下，橫向位移大於直向時把旋轉目標拉回起點；第 752–754 行在放開時換標本。提示文字卻是 `DRAG · SCROLL`（約第 668 行）。桌面可以水平拖曳做偏航，頁面沒有距離控制。

建議：桌面滾輪縮放，Shift 或方向鍵才換標本。手機用橫向拖曳旋轉，換標本只留給底部名單或明確的滑動條。

驗收：桌面拖曳可繞標本一圈，滾輪只改變距離。390px 寬的畫面橫向拖曳也是旋轉，不會跳到下一隻；點名單才換。

### 6. 從缸內到標本頁再回來，位置不會保留

資訊卡與加號（`index.html` 第 1607–1616 行）前往 `showcase.html?id=`。`showcase.html` 第 162 行的返回只連到 `index.html`。`index.html` 不讀 `id`、`code` 或 hash，所以永遠回到封面，不會進缸，也不會對準剛才那一隻。

`showcase.html` 第 679–701 行只在啟動時讀一次網址，沒有 `hashchange`。`SITE_ARCHITECTURE.md` 第 79 行寫了 hash 導覽，程式沒有這段。`?id=` 第一次開啟有效，開啟後改 hash 無效。

建議：返回網址帶上標本代號與 `inside`。`index.html` 讀到代號就進缸並聚焦。`showcase.html` 監聽 `hashchange` 與 `popstate`。

驗收：在缸內打開巴拉望，進標本頁，按返回，應回到缸內的巴拉望，而不是封面。開啟後把 hash 改成 `#0800`，畫面要換成戰神大兜。

## P1 未實測的執行風險

這些分支在程式裡存在。這次沒有看到它們是否在現有模型上發生。

- 座位偵測若得到空清單，第 1413–1415 行顯示「偵測失敗」，第 1421–1422 行不會點亮 OPEN，第 1722–1723 行也拒絕進入。沒有重試。
- 第 637–649 行的落點，以及第 999–1007 行寫死的缸內範圍（X ±1.88、Y 0.94–3.12、Z -0.80–0.68），是對單一缸體尺寸的耦合。模型或縮放一變，標本可能懸空、陷入或被推出玻璃。
- WebGL context 恢復時，`index.html` 第 484–498 行與 `showcase.html` 第 309–320 行只重開動畫迴圈，不重建幾何與材質。中斷後可能黑畫面。
- 寬於 768px 的觸控裝置：畫布第 43 與第 472 行是 `touch-action: none`，直向拖曳改捲動只在 `mobileLayout()`（第 442–443、1780 行）成立時發生。平板橫向可能既不能原生捲動，也不能推鏡頭路徑。

建議與驗收：偵測失敗要給重試，不要鎖死封面。改缸體後用每一隻標本檢查腹面間隙與是否留在玻璃內。模擬 context lost 後標本與缸還在。1024px 寬的觸控畫面仍能推進度條。

## P2 改善

- 資訊卡在 `.visible` 時可點（第 211–213 行），點整張就離開（第 1613–1616 行）。手機版卡在底部（第 335–347 行），會吃掉下半部拖曳。建議只有加號與分享可點。
- 選卡沒有滯後（第 1638–1663 行），鏡頭掃過時名稱可能來回跳。
- 慣性只有偏航（第 1900–1905 行），俯仰一放開就停。
- RESET 只在 `phase === 'inside'` 生效（第 1752–1760 行），進入動畫中按了沒反應。
- `resize` 只重算畫布（第 1924 行），沒有 `ScrollTrigger.refresh()`。
- 第 600–602 行一次預載全部標本；`showcase.html` 第 669–671 行第一隻成功後立刻預載其餘全部，沒有同時數量上限。
- 複製連結失敗時兩邊都是空的 `catch`（index 第 1629–1634 行，showcase 第 269–274 行），按鈕不會說明失敗。
- `prefers-reduced-motion` 下，showcase 第 779–799 行仍讓標本上下浮動並移動塵點。
- 找不到代號時仍顯示第一隻，同時寫「找不到此標本」（showcase 第 693–701、667 行）。
- `showcase.html` 第 523–564 行仍下載生態箱外殼，和標本搶頻寬。這是載入競爭，不是這份稽核要改的範圍，原檔維持不動。

## 建議修復順序

先修捲動容器、放置競態、標本頁的旋轉與縮放分工、返回時回到原標本。其餘等有瀏覽器證據再動。
